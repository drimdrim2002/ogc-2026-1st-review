준비: 최적화 문제란 무엇이고, 왜 어려운가

이 책은 2026년에 열린 최적화 경진대회 OGC 2026에서 1등을 한 프로그램이 어떻게 동작하는지를 처음부터 끝까지 설명합니다. 본론에 들어가기 전에, 이 장에서 책 전체에 쓰이는 말과 읽는 법을 먼저 정리합니다.

이 장을 읽으면 알게 되는 것

최적화 문제를 이루는 네 가지 말(결정 변수, 제약, 목적 함수, 해)의 뜻. 가능한 답을 전부 해 볼 수 없는 이유. 그럴 때 쓰는 세 가지 방법(탐욕법, 지역 탐색, 휴리스틱)의 뜻. 이 책에 나오는 수학 기호와 컴퓨터 용어, 그림과 코드를 읽는 법.

미리 알아야 할 것

고등학교 수학(경우의 수, 수열, 지수와 로그, 좌표평면)과, 변수·조건문·반복문·함수·리스트를 쓰는 정도의 코딩 경험이면 됩니다. 최적화나 알고리즘을 따로 배운 적이 없어도 됩니다.

1부 · 작은 문제 하나로 배우는 최적화의 말

한 칸짜리 작업장 문제

아주 작은 문제부터 봅니다. 작업장이 하나 있고, 한 번에 블록 하나만 들어갑니다. 블록 세 개 가, 나, 다가 0일에 모두 도착해 있습니다. 블록마다 작업에 걸리는 날수와 약속한 완성일(납기)이 있습니다.

블록작업 기간납기
가5일4일
나1일5일
다1일5일

블록이 납기보다 늦게 끝나면 늦은 날수만큼 벌점을 받습니다. 일찍 끝내도 상은 없습니다. 세 블록의 벌점 합을 가장 작게 하려면 어떤 순서로 작업해야 할까요?

이 문제에서 우리가 쓰는 말 네 가지를 정리합니다. 이 책 끝까지 같은 뜻으로 씁니다.

말뜻이 작은 문제에서는
결정 변수우리가 값을 정할 수 있는 것세 블록의 작업 순서
제약반드시 지켜야 하는 규칙. 어기면 답으로 인정되지 않는다한 번에 블록 하나만 작업한다
목적 함수답이 얼마나 좋은지를 숫자 하나로 매기는 식. 결정 변수의 값을 넣으면 점수가 나오는 함수세 블록의 늦은 날수의 합(작을수록 좋다)
해결정 변수에 값을 모두 정한 것 하나순서 하나. 예: 가 → 나 → 다

해에는 등급이 있습니다. 제약을 모두 지키는 해를 유효한 해(실행 가능한 해라고도 합니다)라고 하고, 유효한 해 가운데 목적 함수 값이 가장 좋은 것을 최적해라고 합니다. 최적화 문제는 "제약을 지키면서 목적 함수 값이 가장 좋은 해를 찾아라"라는 문제입니다.

전부 해 보기

블록이 세 개이면 순서는 3! = 3 × 2 × 1 = 6가지뿐입니다. 전부 계산해 봅니다. 예를 들어 가 → 나 → 다 순서라면 가는 0일에 시작해 5일에 끝나고(납기 4일보다 1일 늦음), 나는 5일에 시작해 6일에 끝나고(납기 5일보다 1일 늦음), 다는 7일에 끝납니다(2일 늦음). 벌점 합은 1 + 1 + 2 = 4입니다.

순서끝나는 날 (가, 나, 다)늦은 날수 (가, 나, 다)벌점 합
가 → 나 → 다5, 6, 71, 1, 24
가 → 다 → 나5, 7, 61, 2, 14
나 → 가 → 다6, 1, 72, 0, 24
다 → 가 → 나6, 7, 12, 2, 04
나 → 다 → 가7, 1, 23, 0, 03
다 → 나 → 가7, 2, 13, 0, 03

최적해는 작은 블록 둘을 먼저 하고 큰 블록 가를 맨 뒤로 미루는 순서이고, 그때의 벌점 합은 3입니다. 납기가 가장 빠른 가를 맨 뒤로 보내는 것이 답이라는 점이 조금 뜻밖입니다. 가는 어차피 늦을 수밖에 없고(작업 5일, 납기 4일), 가를 먼저 하면 그 5일 동안 나와 다까지 함께 늦어지기 때문입니다. 이 관찰은 2장에서 실제 문제의 핵심으로 다시 나옵니다.

왜 전부 해 볼 수 없는가

블록이 3개일 때는 6가지를 전부 계산했습니다. 블록이 늘어나면 어떻게 될까요? 블록 n개를 줄 세우는 방법은 n!가지이고, 이 수는 n이 커질 때 상상하기 어려울 만큼 빨리 커집니다.

블록이 5개 늘 때마다 걸리는 시간이 수십만 배에서 수백만 배씩 늘어납니다. 컴퓨터가 천 배 빨라져도 블록 두세 개를 더 다룰 수 있을 뿐입니다. 이렇게 문제의 크기가 조금 커질 때 가능한 해의 수가 곱절로 불어나는 현상을 조합 폭발이라고 부릅니다.

이 책이 다루는 실제 문제는 블록이 100~300개이고, 순서만이 아니라 블록마다 작업장, 놓는 방향, 놓는 좌표, 들어가는 날까지 정해야 합니다. 전부 해 보는 방법은 처음부터 불가능합니다. 게다가 대회는 문제 하나에 몇 분밖에 주지 않습니다.

그래서 목표를 바꿉니다. "가장 좋은 해"를 찾는 대신 "주어진 시간 안에 찾을 수 있는 한 가장 좋은 해"를 찾습니다. 최적해라는 보장은 없지만 짧은 시간에 좋은 해를 찾아 주는 방법을 통틀어 휴리스틱(heuristic)이라고 합니다. 이 책 전체가 잘 만든 휴리스틱 하나를 뜯어보는 내용입니다. 아래에서 가장 기본이 되는 휴리스틱 두 가지를 작은 문제로 미리 봅니다.

방법 1: 탐욕법 — 지금 가장 좋아 보이는 것을 고른다

탐욕법(greedy)은 결정을 하나씩 차례로 내리되, 매번 그 순간 가장 좋아 보이는 것을 고르고 나중에 되돌리지 않는 방법입니다. 한 칸짜리 작업장 문제에서 흔히 떠올리는 탐욕법은 "납기가 빠른 블록부터"입니다.

이 규칙을 따르면 순서는 가 → 나 → 다이고 벌점 합은 4입니다. 계산은 순식간이지만 최적해(3)는 아닙니다. 탐욕법은 눈앞의 선택만 보고, 그 선택이 뒤에 올 블록들에게 어떤 영향을 주는지는 따지지 않기 때문입니다.

그렇다고 탐욕법이 쓸모없는 것은 아닙니다. 빠르고, 대개 "아주 나쁘지는 않은" 해를 줍니다. 그래서 탐욕법은 주로 출발점이 될 해를 만드는 데 쓰고, 그 해를 다음 방법으로 고쳐 나갑니다.

방법 2: 지역 탐색 — 조금 바꿔 보고, 좋아지면 갈아탄다

지역 탐색(local search)은 해 하나를 들고 시작해서, 그 해를 조금 바꾼 해를 만들어 보고, 더 좋으면 그쪽으로 갈아타는 일을 되풀이하는 방법입니다. "조금 바꾸는 방법"을 이웃이라고 부릅니다. 지금 해에서 한 번 바꿔서 갈 수 있는 해들이 이웃한 집처럼 가까이 있다는 뜻입니다.

작업장 문제에서 이웃을 "나란히 있는 두 블록의 순서를 맞바꾸기"로 정해 봅니다. 탐욕법이 준 해 가 → 나 → 다(벌점 4)에서 출발합니다.

여기서 중요한 일이 생깁니다. 출발 해의 이웃 두 개는 모두 벌점이 4입니다. "더 좋아질 때만 갈아탄다"고 정하면 탐색은 여기서 멈춥니다. 더 좋은 해(벌점 3)가 있는데도 한 걸음 안에는 보이지 않기 때문입니다. 이렇게 어느 이웃으로 가도 더 좋아지지 않는 해를 지역 최적해라고 합니다. 전체에서 가장 좋은 해(최적해)와 구별해서 부르는 이름입니다.

규칙을 "같거나 좋아지면 갈아탄다"로 바꾸면 길이 열립니다. 가 → 나 → 다(4)에서 나 → 가 → 다(4)로 옮기고, 거기서 다시 한 번 맞바꾸면 나 → 다 → 가(3)에 닿습니다. 당장 좋아지지 않는 걸음을 한 번 받아들여야 더 좋은 곳에 갈 수 있었습니다.

이웃을 다르게 정하면 지역 최적해도 달라집니다. 만약 이웃을 "블록 하나를 뽑아 아무 자리에나 다시 끼우기"로 정했다면, 가 → 나 → 다에서 가를 뽑아 맨 뒤에 끼워 한 걸음에 최적해로 갈 수 있습니다. 좋은 이웃을 설계하는 일이 지역 탐색의 핵심이고, 7장 전체가 그 이야기입니다.

여기까지의 요약

전부 해 보는 것은 불가능하다(조합 폭발). 그래서 휴리스틱을 쓴다. 탐욕법으로 출발 해를 빨리 만들고, 지역 탐색으로 조금씩 고친다. 지역 탐색은 지역 최적해에 갇히므로 거기서 빠져나올 장치가 필요하다. 이 책의 1등 해법도 큰 틀에서는 이 순서를 따릅니다.

컴퓨터 용어

말뜻
알고리즘문제를 푸는 절차. 이 책에서는 "이 해법", "솔버"와 거의 같은 뜻으로 씁니다. 솔버(solver)는 문제를 입력받아 해를 내놓는 프로그램입니다.
JSON자료를 글자로 적는 형식. { } 안에는 "이름: 값" 쌍을, [ ] 안에는 값을 차례로 적습니다. 파이썬의 딕셔너리와 리스트를 그대로 적은 모양입니다.
배열, 목록값을 번호 순서대로 늘어놓은 것(파이썬의 리스트). 번호는 0부터 셉니다. blocks[2]는 세 번째 블록입니다.
정렬목록을 어떤 기준에 따라 줄 세우는 일. 기준이 여럿이면 "첫 기준이 같을 때만 둘째 기준을 본다"는 식으로 적용합니다. 학급 석차를 총점으로 매기고 동점이면 국어 점수로 가리는 것과 같습니다.
난수주사위처럼 무작위로 뽑은 수. 이 책에서 "0~1 난수"는 0 이상 1 미만의 실수를 고르게(어느 값이나 같은 가능성으로) 뽑은 것입니다. "확률 0.7로 고른다"는 0~1 난수를 뽑아 0.7보다 작으면 고른다는 뜻입니다.
코어, 스레드, 워커코어는 컴퓨터 안에서 계산을 하는 일꾼입니다. 코어가 4개이면 네 가지 일을 동시에 할 수 있습니다. 프로그램 안에서 동시에 진행되는 일의 흐름 하나를 스레드라고 하고, 이 책에서는 탐색을 맡은 스레드 하나를 워커(worker)라고 부릅니다. "워커 4개"는 네 명이 각자 자기 해를 들고 동시에 탐색한다는 뜻입니다.
사전계산나중에 여러 번 쓰일 값을 미리 한 번 계산해 저장해 두는 일. 구구단을 외워 두는 것과 같습니다.
파라미터알고리즘의 동작을 조절하는 숫자. "한 번에 20개씩", "확률 0.7" 같은 값입니다. 문제의 입력과 달리 만든 사람이 실험으로 정합니다.
비싸다, 싸다계산에 시간이 많이 든다, 적게 든다는 뜻으로 씁니다.

코드를 적는 방식

원래 프로그램은 Rust라는 언어로 쓰여 있습니다. 이 책은 Rust 코드를 그대로 싣지 않고, 파이썬과 비슷하게 생긴 의사코드로 바꿔 적습니다. 의사코드는 실제로 실행되는 코드가 아니라 절차를 사람이 읽기 좋게 적은 것입니다. 아래처럼 생겼습니다.

# 납기가 빠른 순으로 작업했을 때의 벌점 합
순서 = 블록들을 납기가 빠른 순으로 정렬
지금 = 0
벌점 = 0
for 블록 in 순서:
    지금 = 지금 + 블록.작업기간          # 이 블록이 끝나는 날
    벌점 = 벌점 + max(0, 지금 - 블록.납기)
return 벌점
  • # 뒤는 설명(주석)입니다.
  • for … in …:은 반복, if …:는 조건, return은 결과를 돌려준다는 뜻입니다. 들여쓰기가 묶음을 나타냅니다.
  • 한글로 적은 줄은 그 일을 한다는 뜻이고, 자세한 방법은 본문에서 설명합니다.
  • 코드 아래의 작은 글씨 src/solver/insert.rs:63 같은 표기는 원래 프로그램에서 그 내용이 있는 파일과 줄 번호입니다. 출처를 밝히려고 적은 것이니 건너뛰어도 됩니다.

  • 무늬. 그림은 세 가지 색을 주로 쓰는데, 흑백으로 인쇄해도 구별되도록 색마다 무늬를 넣었습니다. 파랑은 민무늬, 녹색은 점무늬, 주황은 빗금입니다. 본문에서 "주황"이라고 하면 빗금 친 부분입니다.
  • 실제 데이터. 대회가 공개한 연습용 문제 14개가 있습니다(train/ 폴더). 이 책의 숫자와 그림은 대부분 여기서 가져왔고, 문제 이름은 prelim_prob_1(예선 1번)처럼 적습니다. 이 14개를 "학습 데이터"라고 부릅니다.
  • "제가 계산했습니다". 이 책을 쓴 해설자는 대회 프로그램을 직접 실행할 수 없는 환경에서 작업했습니다. 그래서 일부 숫자는 프로그램의 절차를 파이썬으로 따로 옮겨 계산한 것입니다. 그런 숫자에는 "직접 계산", "재현"이라고 표시했습니다. 원래 프로그램이 실제로 낸 값과는 조금 다를 수 있지만, 절차와 식은 모두 원래 코드에서 확인한 것입니다.
  • "실제로는 …". 설명을 쉽게 하려고 단순하게 말한 곳에는 "실제로는"으로 시작하는 문장을 붙여 정확한 내용을 밝혔습니다.
  • "더 알고 싶다면". 장 끝에 있는 이 절은 세부 구현과 출처를 모은 곳입니다. 처음 읽을 때는 건너뛰어도 흐름이 끊기지 않습니다.

이해 확인

한 칸짜리 작업장 문제에서 "한 번에 블록 하나만 작업한다"는 결정 변수, 제약, 목적 함수 중 무엇인가요?

제약입니다. 우리가 고르는 값이 아니라 반드시 지켜야 하는 규칙입니다. 결정 변수는 작업 순서이고, 목적 함수는 늦은 날수의 합입니다.

블록이 4개(가, 나, 다, 라)이면 순서는 몇 가지인가요? 12개이면 대략 얼마인가요?

4! = 24가지입니다. 12! = 479,001,600으로 약 4억 8천만 가지입니다. 블록이 3배가 되었는데 경우의 수는 약 2천만 배가 되었습니다.

본문의 문제에서 납기를 가 6일, 나 5일, 다 5일로 바꾸면 "납기가 빠른 순" 탐욕법의 벌점 합은 얼마인가요? 최적해인가요?

납기가 빠른 순은 나 → 다 → 가(나와 다는 같으므로 어느 쪽이 먼저여도 같습니다)입니다. 나는 1일, 다는 2일, 가는 7일에 끝나므로 늦은 날수는 0, 0, 1이고 합은 1입니다. 가는 혼자 맨 먼저 해도 5일에 끝나 늦지 않지만, 그러면 나와 다가 6일, 7일에 끝나 합이 3이 됩니다. 여섯 가지를 모두 해 보면 1이 가장 작으므로 이번에는 탐욕법의 해가 최적해입니다. 탐욕법은 맞을 때도 있고 틀릴 때도 있으며, 미리 알기 어렵다는 점이 문제입니다.

지역 최적해와 최적해는 어떻게 다른가요?

지역 최적해는 "정해 둔 이웃 안에서는 더 좋은 해가 없는" 해입니다. 최적해는 유효한 해 전체에서 가장 좋은 해입니다. 최적해는 항상 지역 최적해이지만, 지역 최적해가 최적해라는 보장은 없습니다. 본문에서 가 → 나 → 다(벌점 4)는 "맞바꿔서 좋아질 때만 이동"이라는 규칙에서는 지역 최적해이지만 최적해(벌점 3)는 아닙니다.
