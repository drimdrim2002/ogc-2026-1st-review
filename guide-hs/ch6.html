롤링 호라이즌: 스무 개씩 넣고, 넣을 때마다 전체를 다시 고친다

2장에서 본 2단계의 뼈대는 반복문 하나입니다. 투입 순서대로 블록을 20개쯤 추가하고(확장), 지금까지 들어온 블록 전체를 SA로 고치고, 다시 20개를 추가합니다. 이 장은 그 반복문이 시간과 해를 어떻게 굴리는지, 그리고 마지막에 해가 프로그램 밖으로 나가 대회에 제출되기까지를 따라갑니다.

이 장을 읽으면 알게 되는 것

블록 100~300개를 스무 개씩 나누는 법과 뒤쪽 호라이즌에 시간을 몰아주는 식. 새 블록을 넣을 때 기존 블록 몇 개를 같이 빼서 섞어 넣는 이유(확장). 워커 4개가 각자 해를 따로 들고 가는 이유. 작업량 균형(w₂)을 마지막에만 켜는 이유. 그리고 제한 시간 안에 반드시 유효한 해를 돌려주기 위한 안전장치.

미리 알아야 할 것

0장의 워커·시드 개념. 1장의 목적 함수(w₁, w₂, w₃)와 −1점 벌칙, 같은 날 EXIT 먼저 규칙. 2장의 2단계 전체 흐름. 3장의 추상 일정과 투입 순서. 5장의 탐욕 삽입과 가지치기, 앵커.

원래 프로그램에서는 src/solver/optimize.rs(롤링 호라이즌과 확장), src/solver/output.rs(후보 해 출력), tools/myalgorithm.py(파이썬 실행·검증 래퍼)입니다. 이 장의 시간 수치는 params/default.yaml의 값과 코드의 식으로 계산한 명목 값입니다.

1부 · 숫자로 보는 호라이즌

블록을 몇 개씩, 몇 번으로 나누나

호라이즌의 수와 크기는 전체 블록 수 N만으로 정해집니다. 20개씩 자르고 남는 것을 마지막에 몰지 않습니다. 먼저 호라이즌 개수 H = ⌈N ÷ 20⌉을 정한 뒤, N을 H등분해 고르게 나눕니다.

# 호라이즌 나누기 (src/solver/optimize.rs:250)
호라이즌 수 = ⌈N ÷ 20⌉
for i in 0, 1, …, 호라이즌 수 − 1:
    시작 = ⌊N × i ÷ 호라이즌 수⌋
    끝   = ⌊N × (i + 1) ÷ 호라이즌 수⌋
    i번째 호라이즌 = 투입 순서 목록[시작 .. 끝 앞까지]

그래서 20은 한 호라이즌 크기의 상한입니다. N = 150이면 20개짜리 7개와 10개짜리 1개가 아니라, 18~19개짜리 8개가 됩니다. 학습 데이터 14개의 블록 수는 100, 150, 200, 250, 300 다섯 가지뿐이라 이렇게 정리됩니다.

2부 · 호라이즌 하나 안에서 일어나는 일

한 호라이즌의 시간 구성

호라이즌 하나에서 하는 일은 순서대로 넷입니다. ① 이번 호라이즌의 w₂와 마감을 계산합니다. ② 워커마다 새 블록들을 자기 해에 끼워 넣습니다(확장). ③ 워커들의 해를 SA에 넘겨 마감까지 고칩니다. ④ SA가 돌려준 워커별 해를 다음 호라이즌으로 넘깁니다.

마감은 호라이즌이 시작될 때마다 다시 계산한다

호라이즌 h의 가중치는 (누적 블록 수)γ이고, 기본값은 γ = 2입니다. 즉 누적 블록 수의 제곱에 비례해 시간을 줍니다. 중요한 점은 시간표를 처음에 고정해 두지 않고, 호라이즌이 시작될 때마다 "지금 남은 시간"을 남은 호라이즌들의 가중치 비율로 다시 나눈다는 것입니다.

이번 몫 = max(0, 전체 마감 − 지금) × (이번 가중치) ÷ (이번 것부터 끝까지의 가중치 합)

모든 호라이즌이 제 시간에 끝나면 처음에 한 번 나눈 것과 같습니다. 그런데 만약 어느 호라이즌이 예정보다 늦게 끝나면 어떻게 될까요? 남은 호라이즌들이 늦어진 만큼을 가중치 비율대로 나눠서 덜 받습니다. 그리고 마지막 호라이즌에서는 이번 가중치와 남은 가중치 합이 같으므로 마감이 정확히 전체 마감(295초)이 됩니다.

T = 300, 블록 250개에서 호라이즌 9가 예정보다 5초 늦게 끝났다고 가정하고 계산해 보면 이렇습니다.

확장: 기존 블록을 몇 개 같이 빼서 섞어 넣는다

새 블록 20개를 기존 일정의 맨 뒤에 그냥 덧붙이지 않습니다. 기존 블록 7~13개를 함께 빼낸 뒤, 새 블록 20개와 섞어서 한꺼번에 다시 넣습니다. 이 한 번을 시도(trial)라고 부르고, 확장 마감 시간이 될 때까지 여러 번 시도해 가장 점수가 좋은 결과 하나만 남깁니다.

# 확장: 새 블록 끼워 넣기 (src/solver/optimize.rs:303)
최선 = 없음
while True:
    if 최선이 있고 지금 >= 확장 마감: break          # 완성된 해가 하나는 있어야 끝난다

    # ① 기존 일정에서 7~13개를 골라 뺀다 (첫 호라이즌이면 건너뜀)
    뺄 목록 = 기존 일정에서 가까이 있는 블록 7~13개 고르기
    남은 일정, 남은 점수 = 기존 일정에서 뺄 목록을 제외한 것

    # ② 뺀 블록 + 새 블록을 섞어 줄 세운다 (시도마다 가중치가 달라진다)
    넣을 목록 = 줄 세우기(뺄 목록 + 새 블록 목록)

    # ③ 순서대로 하나씩 탐욕 삽입 (5장)
    성공 = True
    for 블록 in 넣을 목록:
        if 최선이 있고 남은 점수 >= 최선의 점수:     # 가지치기
            성공 = False; break
        자리 = 탐욕 삽입(블록, 입고 범위 = [R, 무한대], 기준 지연)
        남은 일정에 자리를 추가하고, 남은 점수를 갱신
    if not 성공: continue

    # ④ 전체 점수(w₂ 항 포함)를 매겨 최선과 비교
    후보 점수 = 남은 점수 + w₂ × Z₂(남은 일정)
    if 최선이 없거나 후보 점수 < 최선의 점수: 최선 = (남은 일정, 후보 점수)
    if 최선의 점수 == 0: break                       # 0점이면 더 볼 것이 없다
return 최선
  • 시도는 매번 같은 출발 해에서 시작합니다. 앞 시도의 결과를 이어 고치는 것이 아니라, 워커가 들고 온 원래 해에서 매번 새로 7~13개를 뽑아 다른 순서로 넣어 봅니다. 고쳐 나가는 일은 그 뒤의 SA가 맡습니다.
  • 가지치기가 시도를 빨리 끊어 줍니다. 블록을 하나 넣을 때마다 지금까지 쌓인 지연 + 선호 벌점이 "지금까지의 최선 점수" 이상이 되면, 남은 블록을 넣어 보지 않고 그 시도를 버립니다. 블록을 더 넣을수록 벌점은 늘기만 하고(0 미만일 수 없음), 마지막에 더해질 작업량 균형 항(w₂·Z₂)도 0 이상이므로 끝까지 가도 최선을 이길 수 없기 때문입니다.
  • 입고 시각에 위 한계가 없습니다. 새 블록은 얼마나 늦어지든 반드시 일정에 들어가야 하므로, 탐욕 삽입의 입고 시각 범위는 [R, 무한대]입니다. 그래서 주어진 확장 시간이 0초여도 첫 시도는 반드시 성공하고, 새 블록이 빠진 채로 넘어가는 일은 없습니다.
  • 첫 호라이즌에서는. 기존 일정이 비어 있으므로 ①을 건너뛰고, 새 블록 18~20개만 순서를 바꿔 가며 빈 베이에 여러 번 쌓아 본 뒤 가장 좋은 것을 고릅니다.

워커 4개가 각자 해를 따로 들고 간다

확장과 SA는 워커 4개가 각자 자기 해를 들고 동시에 수행합니다. 컴퓨터가 만드는 난수는 시드(seed)라는 출발값에서 계산으로 만들어 내는 수열이라, 시드가 같으면 네 워커가 똑같은 선택을 하게 됩니다. 그래서 워커마다 세 가지를 다르게 줍니다.

워커마다 다른 것값효과
출발하는 해그 워커가 앞 호라이즌에서 얻은 해워커별로 다른 배치 구조가 이어진다
난수 시드기본 시드 + 호라이즌 번호 + 워커 번호뺄 블록, 넣는 순서, 삽입의 무작위 선택이 달라진다
기본 앵커워커 0: 왼쪽 아래, 1: 오른쪽 아래, 2: 왼쪽 위, 3: 오른쪽 위동점일 때 블록을 어느 구석으로 붙일지가 달라진다(5장)

호라이즌이 끝날 때 가장 좋은 해 하나를 골라 네 워커에게 복사해 줄 수도 있었을 것입니다. 그렇게 하지 않고 네 해를 나란히 키우는 이유는, 지금 당장 점수가 1등인 앞쪽 배치가 나중에 들어올 블록들에게도 최선이라는 보장이 없기 때문입니다. 서로 다른 구석부터 채운 네 가지 구조를 끝까지 끌고 가되, SA 도중 크게 뒤처진 워커만 공유 최선을 내려받아 따라잡게 합니다(7장).

또 하나, SA가 끝났을 때 다음 호라이즌으로 넘기는 것은 SA 마지막 순간의 "현재 해"가 아니라 그 워커가 이번 SA 동안 찾은 개인 최선입니다. 온도가 남아 있어서 현재 해가 잠깐 나빠진 채로 끝나더라도, 그 손해가 다음 호라이즌으로 넘어가지 않습니다.

SA는 두 경우에 건너뜁니다. ① 확장 직후 이미 최선이 0점일 때(고칠 것이 없음), ② 확장이 끝났을 때 이미 이번 호라이즌의 마감이 지났을 때(시간이 부족해 확장만 하고 넘어감)입니다.

3부 · 작업량 균형(w₂)은 마지막 호라이즌에서만 켠다

중간 호라이즌에서는 w₂ = 0

목적 함수에는 세 항이 있습니다. 납기 지연(w₁·Z₁), 베이 간 작업량 불균형(w₂·Z₂), 선호도 벌점(w₃·Z₃)입니다. 롤링 호라이즌은 마지막 호라이즌이 되기 전까지 w₂를 0으로 꺼 둡니다.

이유는 2장에서 본 대로입니다. 블록이 절반밖에 안 들어왔을 때 베이들의 작업량을 맞춰 봐야, 뒤에 들어올 블록들이 선호하는 베이가 한쪽으로 쏠려 있으면 균형이 다시 깨집니다. 반대로 마지막 호라이즌이 시작되면 맨 처음부터 공식 w₂를 켭니다. 앞 호라이즌에서 w₂ = 0으로 매긴 점수는 버리고, 새 w₂로 점수를 처음부터 다시 계산합니다.

w₂가 0인 동안에는 탐욕 삽입 안에서도 Z₂ 계산을 통째로 건너뛰므로 속도도 빨라집니다. 저자는 진행률에 따라 w₂를 서서히 올리는 방식(예: 10% → 30% → … → 100%)도 실험해 보았지만, 부담만 늘고 뚜렷한 이득이 없어 최종 설정에서는 껐습니다.

4부 · 해가 솔버 밖으로 나가기까지

안전장치: 시간 여유 세 겹과 후보 검증

대회 채점에서 무효한 해, 시간 초과, 비정상 종료는 모두 그 문제에서 −1점입니다(1장). 유효한 해는 점수가 조금 나빠도 −1점보다 훨씬 낫습니다. 그래서 대회 채점기가 부르는 파이썬 프로그램(tools/myalgorithm.py)과 Rust 솔버 사이에 여러 겹의 안전장치를 두었습니다.

  • 왜 마지막 호라이즌에서만 내보내나. 중간 호라이즌에는 아직 안 들어온 블록이 있어 제출해도 무효입니다. 그래서 모든 블록이 처음 다 들어간 순간(마지막 호라이즌의 확장 직후)에 첫 후보를 강제로 내보내고, 그 뒤 SA 도중 더 좋은 해가 나오면 일정 간격(최소 10초, 또는 마지막 호라이즌 몫의 1/10)마다 내보내며, 종료 직전에 마지막 해를 한 번 더 내보냅니다.
  • 같은 날에는 EXIT를 먼저 적는다. 일정에서 대회 형식(JSON)을 만들 때, 먼저 모든 블록의 EXIT를 각 출고일에 적고, 그다음 모든 블록의 ENTRY를 각 입고일에 적습니다. 어느 날짜에서든 EXIT가 ENTRY보다 앞에 오게 해, 같은 날 나간 자리에 바로 들어오는 배치가 규칙을 어기지 않게 합니다(1장).
  • 다른 방법으로 다시 검증한다. 솔버가 끝나면(또는 T − 1초에 강제 종료되면) 파이썬 쪽이 모아 둔 후보들을 점수가 좋은 순으로 줄 세우고, 1등부터 직접 다각형 교차를 계산해 규칙을 어긴 곳이 없는지 검사합니다. 솔버는 미리 계산한 충돌 격자(4장)를 썼고, 파이썬은 다각형 교차(다른 방법)로 확인하므로, 혹시 모를 버그로 1등이 무효여도 다음 유효 후보를 안전하게 제출할 수 있습니다.

더 알고 싶다면

  • 확장의 시도는 7장의 큰 재구성 이웃과 같은 부품을 씁니다. 뺄 블록을 고르고, 섞어 줄 세우고, 하나씩 탐욕 삽입하는 과정이 같습니다. 차이는 확장이 새 블록을 함께 넣는다는 점, 매번 같은 출발 해에서 시작한다는 점, 그리고 입고 시각에 위 한계가 없다는 점입니다.
  • 검증까지 시간이 안 남으면. 만약 검증 도중 T − 1초에 닿으면 검사를 멈추고 그때까지 모인 후보 중 점수 1등을 그대로 돌려줍니다. 시간 초과로 −1점을 받는 것보다 훨씬 안전하기 때문입니다.
  • 저자의 보고서와 조금 다른 곳. 보고서의 의사코드(Algorithm 1)는 확장을 먼저 하고 그 뒤에 w₂와 시간 배분을 정하는 순서로 적었지만, 실제 코드는 w₂와 마감을 먼저 계산하고 확장에도 그 w₂와 시간 몫(5%)을 씁니다. 또 보고서는 확장의 재삽입 순서를 "무작위 순서"라고 줄여 적었지만, 코드는 3장의 가중 점수 순(시도마다 가중치와 난수를 새로 뽑음)을 씁니다.

이해 확인

블록 150개 문제는 호라이즌이 몇 개이고, 하나에 블록이 몇 개씩 들어가나요?

⌈150 ÷ 20⌉ = 8개입니다. 150을 8로 고르게 나누므로 18개짜리 2개와 19개짜리 6개가 됩니다. 20개씩 7번 넣고 10개를 남기는 방식이 아닙니다.

어느 호라이즌의 SA가 예정보다 10초 늦게 끝났습니다. 전체 마감(295초)은 넘기게 되나요?

아니요. 다음 호라이즌이 시작될 때마다 "전체 마감 − 지금"을 남은 호라이즌들의 가중치 비율로 다시 나누기 때문입니다. 늦어진 10초는 남은 호라이즌들이 비율대로 나눠서 덜 받습니다.

확장에 주어진 시간이 0초여도 새 블록은 일정에 들어가나요?

들어갑니다. 확장은 "완성된 해가 하나 이상 있고 시간이 지났을 때"만 끝나므로 첫 시도는 반드시 끝까지 갑니다. 입고 시각에 위 한계도 없어서 삽입이 실패하지 않습니다.

확장의 한 시도에서 블록 4개만 넣고 중간에 그만두는 일이 있습니다. 왜 그래도 되나요?

이미 놓인 블록들의 지연 + 선호 벌점 합이 지금까지의 최선 점수 이상이 되었기 때문입니다. 남은 블록을 더 넣어도 벌점은 줄어들지 않고, 마지막에 더해질 w₂·Z₂도 0 이상이므로 끝까지 가도 최선을 이길 수 없습니다.

왜 중간 호라이즌에서는 w₂를 0으로 두고, 후보 해 출력도 하지 않나요?

중간 호라이즌에는 아직 안 들어온 블록이 남아 있어 작업량 균형을 미리 맞춰 봐야 나중에 깨지기 때문에 w₂를 끕니다. 마찬가지로 블록이 빠진 해는 제출해도 무효이므로, 모든 블록이 다 들어온 마지막 호라이즌부터만 후보를 내보냅니다.

대회 제한이 300초인데 솔버가 299초까지 안 끝나면 어떻게 되나요?

파이썬 쪽이 299초에 솔버를 강제 종료하고, 그때까지 출력된 후보 해를 읽습니다. 검증할 시간은 없으므로 점수가 가장 좋은 후보를 바로 돌려주어 시간 초과(−1점)를 피합니다.
